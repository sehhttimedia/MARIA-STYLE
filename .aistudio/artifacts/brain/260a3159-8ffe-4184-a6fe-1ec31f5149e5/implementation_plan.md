# Centralized Server Persistence & Multi-Device Admin Engine

خطة هندسية شاملة لتثبيت وتوحيد بيانات لوحة التحكم والمتجر لجميع الأجهزة والمتصفحات، وإضافة أزرار حفظ صريحة لكل قسم، وحل مشاكل بطء الفتح والشاشة البيضاء عبر شاشة تحميل فائقة السرعة لا تحجب التفاعل.

## User Review & Critical Decisions

> [!IMPORTANT]
> تم تأكيد القرارات التصميمية والمعمارية الأساسية بناءً على إجاباتك في المرحلة الأولى:

- **Confirmed Decision 1 (Storage Architecture)**: قاعدة بيانات الخادم المركزية الدائمة (`/data/*.json`) هي المصدر الحصري الموثوق لكافة البيانات (`CMS`, `Products`, `Awards`, `Members`, `Leads`, `Bookings`)، مع إلغاء الاعتماد على الكاش المحلي كحالة ابتدائية تمنع ظهور التعديلات في المتصفحات الجديدة.
- **Confirmed Decision 2 (Save Actions UX)**: إضافة شريط تحكم عائم وثابت (Sticky Header) أعلى كل قسم في لوحة التحكم يحتوي على زر "حفظ التعديلات في ملفات الموقع"، ومؤشر حالة فوري يبين هل هناك تعديلات غير محفوظة أو تم الحفظ بنجاح، مع إشعار Toast أخضر.
- **Confirmed Decision 3 (Instant Opening Experience)**: تجربة فتح فورية للموقع مع تلاشٍ ناعم وشعار راقٍ غير حاجب (Non-blocking Luxury Brand Fade) ينتهي تلقائياً خلال أجزاء من الثانية ويضمن عدم حدوث شاشة بيضاء أو الحاجة لعمل Refresh من الجوال.

## 1. Overview & Core Concept

- **What It Does**: 
  1. توحيد قراءة وكتابة البيانات في ملفات الخادم مباشرة بحيث يرى أي زائر من أي هاتف محمول أو متصفح جديد نفس المنتجات والأسعار والتعديلات التي قامت بها الإدارة دون أي تفاوت.
  2. تزويد كل قسم في لوحة التحكم (المنتجات، الأعضاء، الاستشارات، طلبات MLM، إعدادات CMS والأسعار، التكريمات) بزر حفظ علوي عائم وثابت لحفظ التغييرات صراحةً في الخادم بنقرة واحدة.
  3. تسريع وتحسين مسار بدء التشغيل (Cold Start & Fast Hydration) بحذف أي مؤقتات معطلة أو استدعاءات خارجية معطلة (Firestore blocks) واستبدالها بتحميل أولي سريع وخفيف.
- **Target Audience**: مدام فاطمة وفريق إدارة منصة ماريا ستايل، إلى جانب زائرات المتجر وعضوات التسويق الشبكي عبر الهواتف والمتصفحات في جميع الدول.
- **Key Value**: الثقة التامة بأن كل تعديل يتم في لوحة التحكم محفوظ بشكل دائم وموحد في الخادم ويظهر لحظياً للجميع، وسرعة فائقة في فتح المتجر بدون شاشات بيضاء.

## 2. User Experience & Visual Design

### A. Sticky Save Action Bar in Dashboard Sections
في أعلى كل تبويب من تبويبات لوحة التحكم (إدارة المنتجات، الفريق والأعضاء، الحجوزات، CMS، التكريمات):
- شريط علوي عائم وثابت (`sticky top-0 z-30`) بخلفية زجاجية راقية (`glass-luxury backdrop-blur-md`).
- يحتوي على:
  - عنوان القسم والوصف المختصر.
  - مؤشر حالة التعديلات: "جميع البيانات متزامنة ومحفوظة" أو "توجد تعديلات غير محفوظة باللون البرتقالي".
  - زر مميز وواضح: **"حفظ التعديلات في ملفات الموقع"** مع أيقونة حفظ وحركة تفاعلية خفيفة، وعند النقر يظهر مؤشر تحميل ثم إشعار نجاح فوري (Toast) ونبضة احتفالية لطيفة.

### B. Non-blocking Luxury Intro & Fast Hydration
- شاشة افتتاحية ذكية للغاية مصممة بأسلوب راقٍ (`opacity-0` fade-in) بشعار ماريا ستايل الذهبي.
- الشاشة **غير حاجِبة (Non-blocking)**؛ أي أن المتصفح يقوم بعرض محتويات الصفحة تحتها فوراً، وتتلاشى الشاشة بنعومة خلال 400ms كحد أقصى بدون إيقاف التفاعل أو حظر شاشات الهواتف.
- في حال تأخر أي مورد شبكي، هناك صمام أمان تلقائي (`Safety Fallback`) يضمن إظهار الموقع فوراً دون تعليق أو حاجة لعمل Refresh.

## 3. Key Product Decisions & Trade-Offs

- **Server-Authoritative State vs. Client LocalStorage**:
  - *Chosen Approach*: الخادم المركزي وملفاته (`server.ts` + `/data/*.json`) هو المصدر الوحيد للبيانات. يتم إلغاء استخدام `localStorage` كقيمة أولية تمنع المتصفحات الجديدة من جلب البيانات، واستخدام مصفوفة بيانات أولية موحدة تتطابق 100% مع ملفات الخادم.
  - *Why*: لأن التخزين في `localStorage` مخصص لجهاز واحد فقط، وعندما يفتح المستخدم من متصفح ثانٍ أو هاتف آخر يقرأ المتصفح ذاكرته الفارغة فيظهر الموقع كأنه بالوضع الافتراضي.
- **Explicit Save Buttons per Tab**:
  - *Chosen Approach*: وضع زر حفظ صريح في كل قسم لحفظ التغييرات دفعة واحدة في ملفات الخادم عبر API مخصص (`/api/products`, `/api/members`, `/api/cms`, etc.).
  - *Why*: يمنح المسؤول شعوراً كاملاً بالأمان والتحكم، ويمنع الحفظ العشوائي أو ضياع البيانات أثناء التنقل بين الحقول.

## 4. Technical Architecture & Data Strategy

```
┌─────────────────────────────────────────────────────────────┐
│                       Admin Dashboard                       │
│  (Sticky Section Bar: "حفظ التعديلات في ملفات الموقع")      │
└──────────────────────────────┬──────────────────────────────┘
                               │  POST / PUT API Request
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 Express Backend (server.ts)                 │
│  - /api/site-data (One-shot unified fast load)              │
│  - /api/products, /api/members, /api/cms, /api/bookings     │
└──────────────────────────────┬──────────────────────────────┘
                               │  Atomic File Commit
                               ▼
┌─────────────────────────────────────────────────────────────┐
│               Site Disk Files (/data/*.json)                │
│  - products.json  - members.json  - cms.json                │
│  - awards.json    - bookings.json - leads.json              │
└──────────────────────────────┬──────────────────────────────┘
                               │  Authoritative Hydration
                               ▼
┌─────────────────────────────────────────────────────────────┐
│          All Visitors & Devices (Mobiles & Desktops)        │
│          Instant 0ms Load + Synchronized Live Data          │
└─────────────────────────────────────────────────────────────┘
```
